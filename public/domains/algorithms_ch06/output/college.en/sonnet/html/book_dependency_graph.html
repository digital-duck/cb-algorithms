Concept Book: Dependency Graph

Payoff

Throughout this chapter we have built, layer by layer, the machinery of directed graphs, adjacency representations, reachability, and topological ordering. The dependency graph is the structure in which all of these tools converge into a single, unified object.

Definition. A dependency graph is a directed acyclic graph $G = (V, E)$ in which each vertex $v \in V$ represents a computational unit—a variable, a task, a module, or an expression—and a directed edge $(u, v) \in E$ asserts that $v$ must be fully evaluated before $u$ can proceed. Formally, if $f_v$ denotes the value or state produced by $v$, then $f_u = \phi_u\!\bigl(\{f_v : (u,v)\in E\}\bigr)$ for some local function $\phi_u$.

Worked example. Consider the arithmetic expression $z = (x + y)^2 - 2x$. Introduce intermediate nodes $a = x + y$, $b = a^2$, $c = 2x$, and $z = b - c$. The dependency graph has edges $z \to b$, $z \to c$, $b \to a$, $a \to x$, $a \to y$, $c \to x$. A topological sort—say $x, y, a, b, c, z$—gives the unique valid evaluation order. Any reverse path from $z$ back to $x$ traces exactly the chain rule of differentiation: $\partial z/\partial x = 2a \cdot 1 - 2$, recovered by accumulating edge weights along that path.

Key theorem (Topological Evaluation Correctness). Let $G$ be a finite DAG and let $\sigma = (v_1, v_2, \dots, v_n)$ be any topological sort of $G$. Evaluating $f_{v_i}$ in the order prescribed by $\sigma$, using only previously computed values, produces a globally consistent assignment. Moreover, every node $v$ with in-degree zero is an independent input, and every node with out-degree zero is a final output; no other ordering guarantees correctness without re-evaluation.

# Lab cell — build and evaluate a dependency graph with SymPy
from sympy import symbols, topological_sort
import networkx as nx

x, y = symbols('x y')
G = nx.DiGraph()
G.add_edges_from([('z','b'), ('z','c'), ('b','a'), ('a','x'), ('a','y'), ('c','x')])
order = list(reversed(list(nx.topological_sort(G))))
print("Evaluation order:", order)

The dependency graph is the natural endpoint of this chapter because it is simultaneously a data structure, an execution model, and a calculus object: its edges encode both control flow and the Jacobian sparsity pattern of any composite function. From this single representation, automatic differentiation reads off gradient computations in $O(|E|)$ time; build systems such as Make or Bazel schedule parallel compilation without redundant work; symbolic algebra kernels in SymPy determine which sub-expressions can be cached and which must be recomputed when a leaf variable changes.

Each application domain is simply a different interpretation of the same abstract object. In automatic differentiation, edge weights become partial derivatives and backward traversal implements the chain rule. In build systems, edge weights become file timestamps and forward traversal implements incremental compilation. In symbolic algebra, sub-expression sharing collapses repeated subtrees into a directed acyclic word graph, reducing both memory and evaluation cost.
