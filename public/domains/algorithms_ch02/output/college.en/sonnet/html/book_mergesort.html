Concept Book: Mergesort

Algorithms Ch02 · Generated by SPL

Payoff

What mergesort achieves. Throughout this book, each concept has sharpened a single instrument in the algorithmic toolkit. Mergesort is the moment those instruments play together. It is a divide-and-conquer sorting algorithm that recursively splits an array of $n$ elements into two halves, sorts each half independently, and then merges the sorted halves into a single sorted sequence. The result is a comparison-based sort with worst-case running time $\Theta(n \log n)$—optimal among all comparison sorts, as the decision-tree lower bound guarantees.

Worked example. Let $A = [5, 2, 8, 1, 9, 3]$. Mergesort divides this into $[5, 2, 8]$ and $[1, 9, 3]$. Each half is sorted recursively, yielding $[2, 5, 8]$ and $[1, 3, 9]$. The merge step scans both sorted lists with two pointers, selecting the smaller front element at each step:

$$[1, 2, 3, 5, 8, 9].$$

At each merge level, exactly $n$ comparisons suffice; there are $\log_2 n$ levels of recursion; hence the total work is $n \log_2 n$ comparisons.

Key theorem. Any deterministic comparison-based sorting algorithm requires at least $\lceil \log_2(n!) \rceil$ comparisons in the worst case. By Stirling's approximation, $\log_2(n!) = \Theta(n \log n)$. Mergesort meets this bound exactly, making it asymptotically optimal. The proof proceeds by modeling every comparison-sort as a binary decision tree of height $h$; since the tree must have at least $n!$ leaves (one per permutation), $2^h \geq n!$, giving $h \geq \log_2(n!)$.

Lab cell.

from sympy import symbols, factorial, log, simplify, N

n = symbols('n', positive=True, integer=True)

# Stirling lower bound on comparisons
lower_bound = log(factorial(n), 2)

# Evaluate for n = 6
print(N(lower_bound.subs(n, 6), 4))   # ≈ 9.49  (mergesort uses ≤ 11)

Mergesort is not merely the fastest general-purpose sort; it is the proof that the concepts built up here—recurrences, divide-and-conquer structure, and information-theoretic lower bounds—are not isolated curiosities but interlocking ideas with real power. The algorithm's stability (equal elements preserve their original order) and its natural parallelism make it foundational in database engines, external sorting of disk-resident data, and the merge step inside timsort, the hybrid algorithm powering Python's built-in sorted().
