Quicksort

Definition. Quicksort is a comparison-based, in-place sorting algorithm that operates by the divide-and-conquer paradigm. Given an array $A[1..n]$, the algorithm selects a pivot element $p \in A$, partitions the remaining elements into two subarrays $L = \{x \in A : x \leq p\}$ and $R = \{x \in A : x > p\}$, and recursively sorts $L$ and $R$. The sorted output is then the concatenation $\text{sort}(L) \cdot p \cdot \text{sort}(R)$. The partition step runs in $\Theta(n)$ time by a single left-to-right scan, maintaining two pointers that swap out-of-place elements.

Worked Example. Consider $A = [3, 6, 8, 10, 1, 2, 1]$. Choose the last element as pivot: $p = 1$.

  • Scan left to right; elements $\leq 1$: $\{1\}$; elements $> 1$: $\{3, 6, 8, 10, 2\}$.
  • After partition: $[1, 1, 3, 6, 8, 10, 2]$ with $p = 1$ placed at index 1.
  • Recurse on $L = [1]$ (already sorted) and $R = [3, 6, 8, 10, 2]$.
  • In $R$, take $p = 2$: partition gives $[2, 3, 6, 8, 10]$; recurse further.
  • Final result: $[1, 1, 2, 3, 6, 8, 10]$.

    • Each recursive call reduces the problem size, provided the pivot does not always fall at an extreme.

    Key Theorem (Average-Case Complexity). When the pivot is chosen uniformly at random from the subarray, the expected number of comparisons performed by quicksort on an input of size $n$ satisfies

    $$T(n) = 2(n+1)H_n - 4n,$$

    where $H_n = \sum_{k=1}^{n} \frac{1}{k}$ is the $n$-th harmonic number. Since $H_n = \ln n + O(1)$, we obtain $T(n) = \Theta(n \log n)$ in expectation. In the worst case — a sorted array with a fixed first- or last-element pivot — every partition produces subarrays of sizes $0$ and $n-1$, yielding $T(n) = \Theta(n^2)$. Randomized pivot selection or the median-of-three heuristic makes worst-case inputs exponentially unlikely.

    Lab Cell.

    from sympy import symbols, harmonic, simplify, log, O

n = symbols('n', positive=True, integer=True)

# Average comparisons formula
T_avg = 2*(n + 1)*harmonic(n) - 4*n
print("T(10) =", T_avg.subs(n, 10).evalf(4))

# Confirm asymptotic growth vs n*log(n)
ratio = T_avg / (n * log(n))
print("T(1000)/(1000·ln 1000) =", ratio.subs(n, 1000).evalf(4))

    Running this cell for $n = 1000$ yields a ratio near $2$, confirming that average-case quicksort performs approximately $2n \ln n$ comparisons — about $39\%$ fewer than the worst-case upper bound and competitive with merge sort, which requires exactly $\lceil n \log_2 n \rceil$ comparisons in the best case.
