递归

递归是指一个函数在其定义中调用自身的编程技巧。它将一个复杂问题分解为更小的同类子问题，直到问题简单到可以直接求解为止。每个递归函数都必须包含两个要素：基本情形（base case，直接返回结果，不再递归）和递归情形（recursive case，将问题规模缩小后调用自身）。若缺少基本情形，函数将无限调用自身，最终导致栈溢出。

从阶乘看递归的逻辑

计算 $n!$ 是理解递归的经典入口。其数学定义本身就是递归的：

$$n! = \begin{cases} 1 & n = 0 \\ n \times (n-1)! & n \geq 1 \end{cases}$$

用 Python 直接翻译这个定义：

def factorial(n):
    if n == 0:          # 基本情形
        return 1
    return n * factorial(n - 1)  # 递归情形

print(factorial(5))  # 输出 120

调用 factorial(5) 时，程序依次展开：$5 \times 4! \to 5 \times 4 \times 3! \to \cdots \to 5 \times 4 \times 3 \times 2 \times 1 \times 1$，再逐层返回结果。关键在于：每次调用都让 $n$ 减小 1，保证最终触及基本情形。

实战：用递归遍历嵌套结构

递归真正的威力体现在处理层级不确定的结构上，循环在这里往往力不从心。假设需要计算一个任意嵌套列表中所有整数的总和：

def deep_sum(data):
    total = 0
    for item in data:
        if isinstance(item, list):   # 遇到子列表，递归处理
            total += deep_sum(item)
        else:
            total += item            # 基本情形：直接累加
    return total

nested = [1, [2, [3, 4], 5], [6, 7]]
print(deep_sum(nested))  # 输出 28

此处的"基本情形"是遇到整数时直接返回其值；"递归情形"是遇到列表时再次调用 deep_sum。无论嵌套多少层，结构相同，逻辑不变。

设计递归函数时，建议先问自己两个问题：最小的、可直接回答的情形是什么？ 以及 如何把当前问题缩减为更小的同类问题？ 能清晰回答这两个问题，递归结构便自然浮现。
