What Fast Exponentiation Achieves

Throughout this text we have built, layer by layer, the arithmetic of repeated multiplication. We studied divisibility, prime factorisation, modular congruences, and the group structure of $\mathbb{Z}/n\mathbb{Z}$. Each of these tools was essential, yet they would remain largely academic without an efficient means of computing large powers. Fast exponentiation — also called binary exponentiation or exponentiation by squaring — is that means.

Definition. Let $a$ be an element of a monoid $(M, \cdot)$ and let $n \in \mathbb{N}$ with binary representation $n = \sum_{k=0}^{\lfloor \log_2 n \rfloor} b_k 2^k$. The fast exponentiation algorithm computes $a^n$ by accumulating only the factors $a^{2^k}$ for which $b_k = 1$, building each successive square from its predecessor.

Worked Example. Compute $3^{13} \pmod{17}$. Write $13 = (1101)_2$, so $13 = 8 + 4 + 1$.

$$3^1 = 3, \quad 3^2 = 9, \quad 3^4 \equiv 81 \equiv 13, \quad 3^8 \equiv 13^2 = 169 \equiv 16 \pmod{17}.$$

Multiplying the flagged powers:

$$3^{13} \equiv 3^8 \cdot 3^4 \cdot 3^1 \equiv 16 \cdot 13 \cdot 3 = 624 \equiv 624 - 36 \cdot 17 = 12 \pmod{17}.$$

Only six multiplications were required; naïve repeated multiplication would have needed twelve.

Key Theorem. For any $n \geq 1$, the algorithm terminates in $O(\log n)$ multiplications. Because each multiplication in $\mathbb{Z}/m\mathbb{Z}$ costs $O((\log m)^2)$ bit-operations with schoolbook arithmetic, the full cost is $O((\log n)(\log m)^2)$ — polylogarithmic in both exponent and modulus, making astronomically large modular powers tractable.

Lab Cell (SymPy)

from sympy import mod_inverse
n, base, mod = 13, 3, 17
result = pow(base, n, mod)          # Python's built-in uses fast exponentiation
print(result)                        # 12

This single line conceals the same binary-squaring loop derived above. Python's pow(a, n, m) is not a convenience shortcut — it is the algorithm, operating in $O(\log n)$ steps regardless of how large $n$ grows.

The reach of this result extends immediately into cryptography, where the security of RSA rests on computing $m^e \bmod N$ for $e$ and $N$ hundreds of digits long; into primality testing, where Fermat's little theorem is checked via modular exponentiation in randomised rounds; and into combinatorics, where matrix exponentiation computes the $n$-th Fibonacci number in $O(\log n)$ multiplications of $2 \times 2$ matrices rather than $O(n)$ additions.

Choose any one of these directions and the machinery you have built here carries you directly inside it.
