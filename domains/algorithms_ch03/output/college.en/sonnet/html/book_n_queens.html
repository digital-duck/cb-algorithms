Concept Book: N Queens

Algorithms Ch03 · Generated by SPL

Payoff

The $n$-queens problem asks: in how many ways can $n$ non-attacking queens be placed on an $n \times n$ chessboard? A queen attacks any square sharing its row, column, or either diagonal, so a valid placement requires that no two queens share any of these lines. Formally, a solution is a permutation $\sigma \in S_n$ such that for all $i \neq j$,

$$|\sigma(i) - \sigma(j)| \neq |i - j|,$$

where queen $i$ occupies row $i$ and column $\sigma(i)$. The row and column constraints are absorbed by the permutation structure; the diagonal conditions are the residual constraints that prune the search space.

Worked Example. For $n = 4$, the candidate space is $4! = 24$ permutations. Applying the diagonal inequality eliminates all but two solutions up to reflection: $\sigma = (2,4,1,3)$ and $\sigma = (3,1,4,2)$. One verifies directly that $|2-4| = 2 \neq |1-2| = 1$, $|2-1| = 1 \neq |1-3| = 2$, and so on for every pair, confirming validity.

Key Theorem (Backtracking Complexity). A naïve generate-and-test algorithm runs in $O(n!)$ time. Systematic backtracking with forward-checking reduces the effective branching factor to approximately $O(n!/c^n)$ for a constant $c > 1$, because each placed queen eliminates a growing fraction of candidate columns for subsequent rows. For $n = 8$, the 92 solutions are found by examining fewer than 2,000 of the $8! = 40{,}320$ leaves, a reduction exceeding 95 percent.

The $n$-queens problem is the natural endpoint of this textbook because it synthesises every layer built before it: combinatorial enumeration supplies the candidate space, constraint propagation prunes it, and recursive backtracking traverses what remains. It is, in miniature, the blueprint for constraint-satisfaction solvers used across scheduling, circuit design, and automated reasoning.

Lab Cell.

from sympy.utilities.iterables import permutations

def queens(n):
    return [
        p for p in permutations(range(n))
        if len({p[i]-i for i in range(n)}) == n
        and len({p[i]+i for i in range(n)}) == n
    ]

print(len(queens(8)))   # → 92

With this single function in hand, you hold the key to an entire family of combinatorial problems. Choose one thread to pull: replace the chessboard with a job-shop schedule, a register-allocation graph, or a Latin square, and you will find that the same constraint-propagation engine, sharpened here on queens, carries you directly to the frontier.
