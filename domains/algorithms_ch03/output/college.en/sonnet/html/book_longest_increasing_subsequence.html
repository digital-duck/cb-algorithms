Concept Book: Longest Increasing Subsequence

Algorithms Ch03 · Generated by SPL

Payoff

The longest increasing subsequence (LIS) of a sequence $a_1, a_2, \ldots, a_n$ is a subsequence $a_{i_1} < a_{i_2} < \cdots < a_{i_k}$ with $i_1 < i_2 < \cdots < i_k$ and $k$ as large as possible. What makes this problem the natural capstone of a first study in dynamic programming is not merely that it is harder than the problems preceding it — it is that its solution crystallizes every major idea encountered along the way: optimal substructure, overlapping sub-problems, and the replacement of naïve search by a principled recurrence — while simultaneously opening doors to a remarkable breadth of applied mathematics.

Why LIS is the natural endpoint. Earlier sections treated recurrences whose sub-problem graph was a path or a grid. LIS introduces a recurrence whose sub-problem graph is a directed acyclic graph determined by the data itself, not fixed in advance. The classical $O(n^2)$ recurrence

$$L(i) = 1 + \max_{\substack{j < i \\ a_j < a_i}} L(j)$$

with $L(i) = 1$ when no valid $j$ exists, forces the student to identify structure that is hidden inside the input. The further refinement to $O(n \log n)$ via patience sorting — maintaining a set of "piles" and exploiting binary search — demonstrates that algorithmic insight, not raw computation, is the lever that moves complexity.

Concrete worked example. Let $(a_i) = (3, 1, 4, 1, 5, 9, 2, 6)$. Applying the recurrence yields $L = (1, 1, 2, 1, 3, 4, 2, 4)$. The value $\mathrm{LIS} = 4$ is attained by, for instance, $1 < 4 < 5 < 9$ or $1 < 2 < 6$ — wait, the latter has length 3; the former length 4. Tracing back through $L$ confirms the answer and illustrates how the recurrence encodes a proof of optimality: any longer subsequence would contradict the maximality of some $L(i)$.

Key theorem (Dilworth, 1950). In any finite partially ordered set, the minimum number of chains needed to cover the set equals the maximum size of an antichain. Applied to a sequence ordered by index and value, this duality implies that the length of the LIS equals the minimum number of non-increasing subsequences required to partition the entire sequence — a result that connects combinatorial optimization to order theory and underpins the patience-sorting algorithm.

from sympy import symbols, Function

# Lab cell: verify L(i) for the worked example
a = [3, 1, 4, 1, 5, 9, 2, 6]
n = len(a)
L = [1] * n
for i in range(1, n):
    for j in range(i):
        if a[j] < a[i]:
            L[i] = max(L[i], L[j] + 1)
print("L =", L)          # [1, 1, 2, 1, 3, 4, 2, 4]
print("LIS length =", max(L))  # 4

The reader who has internalized LIS now holds a key that fits many locks. The patience-sorting interpretation connects directly to card-game combinatorics and the RSK correspondence in algebraic combinatorics. In bioinformatics, finding the LIS of a permutation of gene markers is the first step in computing the edit distance between chromosomal sequences — a tool indispensable in comparative genomics. In version-control systems, the classical diff algorithm reduces to finding common subsequences, the complement of which is governed by the same recurrence. In scheduling theory, minimizing the number of machines needed to execute jobs without overlap is, by Dilworth's theorem, precisely an LIS problem in disguise.

Each of these domains deserves a chapter of its own. The reader is invited to pursue the bioinformatics thread: take two DNA sequences, encode their shared $k$-mers as index pairs, and watch the LIS algorithm reconstruct the skeleton of their evolutionary history. The mathematics is the same; only the data has changed — and that is the deepest lesson of the capstone.
