Concept Book: Finite State Automaton Graph

Payoff

The journey through this text has built, layer by layer, the machinery needed to reason about sequential computation: states, transitions, acceptance conditions, and the graph structures that make those objects manipulable by algorithm. The concept of the finite-state automaton graph is the natural endpoint of that construction because it collapses an abstract machine into a concrete mathematical object — a directed, labeled graph $G = (V, E, \Sigma, \delta, q_0, F)$ — on which every classical tool of graph theory becomes available. Reachability, cycle detection, topological ordering, and shortest-path algorithms all apply without modification. The automaton is no longer a conceptual device; it is data.

Definition. A finite-state automaton graph is a directed multigraph in which each vertex $v_i \in V$ represents a control state, each edge $(v_i, a, v_j) \in E$ encodes the transition $\delta(q_i, a) = q_j$ for input symbol $a \in \Sigma$, one vertex $v_0$ is designated the initial state $q_0$, and a subset $F \subseteq V$ marks the accepting states. A word $w = a_1 a_2 \cdots a_n$ is accepted if and only if the walk starting at $v_0$ and following edges labeled $a_1, a_2, \ldots, a_n$ terminates at a vertex in $F$.

Worked Example. Consider the language $L = \{w \in \{0,1\}^* \mid w \text{ ends in } 01\}$. Construct three states $q_0, q_1, q_2$ with transitions $\delta(q_0, 0) = q_1$, $\delta(q_1, 1) = q_2$, and all other inputs looping back to $q_0$. The graph has vertex set $\{q_0, q_1, q_2\}$, accepting set $F = \{q_2\}$, and five directed edges. A depth-first traversal from $q_0$ confirms every state is reachable, so no dead states exist and the automaton is minimal in vertex count for this language.

Key Theorem (Graph Reachability and Language Emptiness). The language $L(\mathcal{A})$ is non-empty if and only if some vertex in $F$ is reachable from $v_0$ in $G$. Emptiness testing therefore reduces to breadth-first search in $O(|V| + |E|)$ time — a result that would be opaque without the graph representation.

Lab Cell.

import sympy
from sympy.combinatorics.automata import DFA

# Represent the "ends in 01" DFA
states      = [0, 1, 2]
alphabet    = ['0', '1']
transitions = {(0,'0'):1, (0,'1'):0,
               (1,'0'):1, (1,'1'):2,
               (2,'0'):1, (2,'1'):0}
start, accept = 0, {2}

def run(word):
    s = start
    for c in word:
        s = transitions[(s, c)]
    return s in accept

assert run("101")  is True
assert run("100")  is False
print("Accepted:", [w for w in ["01","10","101","001","100"] if run(w)])

The graph-theoretic view now opens a single, particularly powerful door: subset construction. When a language is specified by a nondeterministic automaton — one in which $\delta(q, a)$ may return a set of successor states — the machine cannot be executed directly on a processor that inhabits exactly one state at a time. Subset construction resolves this by building a new automaton whose states are subsets of the original vertex set, converting the powerset lattice $2^V$ into the vertex set of a deterministic graph. Every transition in the new machine is a graph operation: compute the union of successor sets, intersect with reachable subsets, and mark the image as accepting whenever it contains any original accepting vertex.

You have now seen every ingredient that makes subset construction possible: the graph representation of states, edge-labeled transitions, and acceptance defined by vertex membership. The next chapter invites you to work through a full construction by hand, prove that the resulting deterministic automaton accepts precisely the same language as its nondeterministic source, and implement the powerset expansion in SymPy — discovering along the way why the worst-case $2^{|V|}$ blowup is not merely a theoretical curiosity but a boundary that separates tractable compilation from intractable enumeration.
