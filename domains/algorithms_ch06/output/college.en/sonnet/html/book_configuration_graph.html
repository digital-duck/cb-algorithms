What the Configuration Graph Achieves

Throughout this text we have built a precise language for describing how a system's state can change: variables, constraints, reachability, and local search. The configuration graph is the structure that unifies all of these ideas into a single mathematical object.

Definition. Given a system with a finite (or countably infinite) state space $\mathcal{S}$ and a transition relation $\delta \subseteq \mathcal{S} \times \mathcal{S}$, the configuration graph is the directed graph $G = (\mathcal{S}, \delta)$ whose vertices are configurations and whose edges encode one-step transitions. A path $s_0 \to s_1 \to \cdots \to s_k$ in $G$ corresponds to a valid execution of length $k$.

Every question we have asked in preceding chapters — Can we reach state $t$ from state $s$? Is there a shortest path? A cycle? A dead end? — is now a question about graph reachability, shortest paths, strongly connected components, or sink vertices. Graph theory, one of the most thoroughly developed branches of combinatorics, is thereby recruited in its entirety.

Worked Example

Consider the 8-puzzle: a $3 \times 3$ grid with tiles labeled $1$–$8$ and one blank. Each configuration is a permutation $\sigma \in S_9$, so $|\mathcal{S}| = 9! = 362{,}880$. A transition exists between $\sigma$ and $\sigma'$ if and only if they differ by a single slide of the blank. The configuration graph $G$ has exactly $362{,}880$ vertices and is split into two isomorphic connected components (odd and even permutations). The shortest path from any solvable configuration to the goal is computable by breadth-first search on $G$ in $O(|\mathcal{S}|)$ time, and the maximum BFS depth — the diameter of the solvable component — is $31$.

Key Theorem

Theorem (Reachability Dichotomy). In a configuration graph $G = (\mathcal{S}, \delta)$, vertex $t$ is reachable from vertex $s$ if and only if $t$ lies in the same weakly connected component as $s$ in the underlying undirected graph, provided $\delta$ is symmetric; otherwise reachability is determined by the strongly connected component structure of $G$, computable in $O(|\mathcal{S}| + |\delta|)$ time via Tarjan's algorithm.

Proof sketch. Tarjan's depth-first algorithm assigns each vertex a discovery timestamp and a low-link value — the smallest timestamp reachable via back-edges. A vertex $v$ is a root of an SCC precisely when $\text{low}[v] = \text{disc}[v]$. Correctness follows from the invariant that back-edges within a DFS tree witness cycles, which are exactly the intra-SCC edges. $\square$

Lab Cell

import sympy
from sympy.combinatorics import Permutation, PermutationGroup
import networkx as nx

# Build a small configuration graph: 2x2 sliding puzzle (3 tiles + blank)
# Encode each state as a tuple; edges = single blank moves
from itertools import permutations

def neighbors(state):
    s = list(state)
    b = s.index(0)          # blank position
    moves = []
    row, col = divmod(b, 2)
    for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
        r2, c2 = row+dr, col+dc
        if 0 <= r2 < 2 and 0 <= c2 < 2:
            nb = r2*2 + c2
            ns = s[:]
            ns[b], ns[nb] = ns[nb], ns[b]
            moves.append(tuple(ns))
    return moves

states = list(permutations(range(4)))
G = nx.DiGraph()
for s in states:
    for t in neighbors(s):
        G.add_edge(s, t)

sccs = list(nx.strongly_connected_components(G))
print(f"Vertices: {G.number_of_nodes()}, SCCs: {len(sccs)}")
# Shortest path to goal (0,1,2,3)
goal = (0,1,2,3)
start = (3,2,1,0)
path = nx.shortest_path(G, start, goal)
print(f"Optimal moves from {start} to {goal}: {len(path)-1}")

Running this cell reveals the two-component structure and confirms the diameter of the $2 \times 2$ puzzle. The configuration graph makes these facts computable, not merely conjectured.

Invitation

The configuration graph is the natural endpoint of this book because it converts the informal notion of "how a system evolves" into a rigorous, algorithmically tractable object. Every application domain that involves states and rules — constraint satisfaction, planning, protein folding, compiler optimization, game solving — speaks the same graph-theoretic language once its configuration graph is written down.

We invite you now to choose one of these domains and construct its configuration graph from scratch: define the state space precisely, enumerate the transition relation, identify the goal vertices, and answer a reachability question with code. The machinery is in your hands; the discovery is yours to make.
