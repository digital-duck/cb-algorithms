Memoization

Definition. Memoization is a program-optimization technique in which the return value of a deterministic function is stored in a lookup table (the memo table) the first time it is computed; on subsequent calls with identical arguments, the stored result is returned directly, bypassing recomputation. Formally, given a pure function $f : D \to R$, a memoized variant $\hat{f}$ maintains a partial map $M : D \rightharpoonup R$ and satisfies

$$ \hat{f}(x) = \begin{cases} M(x) & \text{if } x \in \operatorname{dom}(M), \\ f(x) \text{ (and set } M(x) \leftarrow f(x)\text{)} & \text{otherwise.} \end{cases} $$

Correctness follows immediately from the assumption that $f$ is pure: because the output depends solely on the input, caching cannot yield a stale result.

Worked Example. Consider the Fibonacci function defined by $F(0)=0$, $F(1)=1$, and $F(n)=F(n-1)+F(n-2)$ for $n \geq 2$. Naive recursive evaluation of $F(n)$ performs $\Theta(\phi^n)$ calls, where $\phi = \frac{1+\sqrt{5}}{2}$ is the golden ratio, because subproblems are recomputed exponentially. With memoization, each distinct argument $k \in \{0,1,\dots,n\}$ is evaluated exactly once, reducing the total call count to $\Theta(n)$. For $n = 6$: the first descent computes $F(6),F(5),\dots,F(0)$ and fills $M$; the ascent returns $1,1,2,3,5,8$ from the table, yielding $F(6)=8$ with no repeated work.

Key Theorem (Memoization Complexity Reduction). Let $T_{\text{naive}}(n)$ denote the time complexity of an unmemoized recursive computation with $S(n)$ distinct subproblems, each solved in $O(w)$ work. Then the memoized complexity satisfies $T_{\text{memo}}(n) = O(S(n) \cdot w)$, compared with $T_{\text{naive}}(n) = \Omega(2^n)$ in the worst case. The space cost of the memo table is $\Theta(S(n))$.

Lab Cell.

import sympy as sp
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n: int) -> int:
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

n = sp.Symbol('n', positive=True, integer=True)
values = [(k, fib(k)) for k in range(11)]
print(values)          # [(0,0),(1,1),(2,1),...,(10,55)]
print(fib.cache_info())  # hits, misses, current size

The decorator lru_cache implements the memo table internally; cache_info() confirms that only $n+1$ misses occur for the first $n+1$ calls, with all subsequent queries served as cache hits.
