What subset\_sum achieves. Throughout this book, each concept has sharpened a single edge of the combinatorial toolkit: sets gave us the language of membership, functions gave us mappings between structures, and recursion gave us the power to reduce a problem to smaller instances of itself. The subset-sum problem is the natural endpoint because it fuses all three. Given a finite set $S = \{s_1, s_2, \ldots, s_n\} \subset \mathbb{Z}$ and a target $T \in \mathbb{Z}$, we ask:

$$\exists\, A \subseteq S \text{ such that } \sum_{a \in A} a = T\,?$$

This single sentence conceals extraordinary depth. Deciding the answer is NP-complete (proved by reduction from 3-SAT), yet instances arising in practice are often tractable, and the search variant — finding $A$ when it exists — exposes every algorithmic idea we have built: brute-force enumeration over $2^n$ subsets, meet-in-the-middle in $O(2^{n/2})$ time, and the celebrated dynamic-programming table that runs in $O(nT)$ pseudo-polynomial time.

Worked example. Let $S = \{3, 1, 4, 2, 6\}$ and $T = 7$. Construct the boolean table $\text{dp}[i][t]$, where a true entry means "target $t$ is reachable using only the first $i$ elements." Initialise $\text{dp}[i][0] = \text{True}$ for all $i$ and $\text{dp}[0][t] = \text{False}$ for $t > 0$. The recurrence is:

$$\text{dp}[i][t] = \text{dp}[i-1][t] \;\lor\; \bigl(t \ge s_i \;\land\; \text{dp}[i-1][t - s_i]\bigr).$$

After processing all five elements, $\text{dp}[5][7] = \text{True}$, witnessed by $A = \{3, 4\}$ (or equivalently $\{1, 6\}$). Backtracking through the table recovers $A$ in $O(n)$ additional steps.

Key theorem. (Pseudo-polynomial complexity) The dynamic-programming algorithm solves subset-sum in $O(nT)$ time and $O(T)$ space (with row-compression). This is polynomial in the value of $T$ but exponential in its bit-length $\lceil \log_2 T \rceil$, which is why NP-completeness and practical tractability coexist: when $T$ is small relative to $n$, the table stays manageable.

Lab cell.

from sympy import symbols, Rational

def subset_sum_dp(S, T):
    dp = [False] * (T + 1)
    dp[0] = True
    parent = [None] * (T + 1)
    for s in S:
        for t in range(T, s - 1, -1):   # iterate right-to-left (0/1 knapsack)
            if not dp[t] and dp[t - s]:
                dp[t] = True
                parent[t] = (t - s, s)
    # backtrack
    if not dp[T]:
        return None
    result, cur = [], T
    while cur > 0:
        cur, chosen = parent[cur]
        result.append(chosen)
    return result

print(subset_sum_dp([3, 1, 4, 2, 6], 7))   # → [4, 3]

Run this cell, then vary $T$ and observe which subsets emerge. Notice that when $T$ exceeds $\sum S$ the function correctly returns None — a boundary case rooted in the definition of the problem itself.
