What Kruskal's Algorithm Achieves

Throughout this text we have assembled the necessary machinery — graphs, edge weights, connected components, and the greedy paradigm — to arrive at one of the most elegant results in combinatorial optimisation. Kruskal's algorithm solves the minimum spanning tree (MST) problem: given a connected, weighted, undirected graph $G = (V, E, w)$ with $w : E \to \mathbb{R}$, it produces a spanning tree $T^* \subseteq E$ such that

$$w(T^*) = \sum_{e \in T^*} w(e)$$

is minimised over all spanning trees of $G$. A spanning tree on $n = |V|$ vertices contains exactly $n - 1$ edges and is acyclic, so $T^*$ is the cheapest acyclic subgraph that keeps every vertex reachable from every other.

The algorithm proceeds by sorting all edges in non-decreasing order of weight and then greedily adding each edge that does not form a cycle with edges already selected, halting once $n - 1$ edges have been accepted. The cycle test is implemented in near-constant amortised time using a union–find (disjoint-set) data structure with path compression and union by rank, yielding an overall running time of $O(|E| \log |E|)$.

Worked Example

Consider the graph with vertices $\{A, B, C, D\}$ and weighted edges

$$\{(A,B,4),\; (A,C,2),\; (B,C,1),\; (B,D,5),\; (C,D,8)\}.$$

Sorting gives the order $(B,C,1), (A,C,2), (A,B,4), (B,D,5), (C,D,8)$. Kruskal's algorithm accepts $(B,C)$, then $(A,C)$, skips $(A,B)$ because $A,B,C$ are already connected, accepts $(B,D)$, and halts. The MST has total weight $1 + 2 + 5 = 8$, strictly less than any alternative spanning tree.

Key Theorem

Theorem (Cut Property). Let $S \subsetneq V$ be any non-empty proper subset of vertices and let $e^$ be a minimum-weight edge crossing the cut $(S, V \setminus S)$. Then $e^$ belongs to some MST of $G$.

This theorem is the rigorous foundation of every greedy edge-acceptance step in Kruskal's algorithm and explains why local cheapness guarantees global optimality.

Lab Cell

import sympy as sp
from sympy.combinatorics import DisjointPaths

edges = [(1, 4, 'A','B'), (2, 4, 'A','C'), (1, 4, 'B','C'),
         (5, 4, 'B','D'), (8, 4, 'C','D')]

edges_sorted = sorted(edges, key=lambda e: e[0])
parent = {v: v for v in ['A','B','C','D']}

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

mst, total = [], 0
for w, _, u, v in edges_sorted:
    if find(u) != find(v):
        parent[find(u)] = find(v)
        mst.append((u, v, w)); total += w

print("MST edges:", mst)
print("Total weight:", sp.Integer(total))

Invitation

The machinery you have just mastered — greedy selection, cycle detection, and the cut property — is the entry point to an entire ecosystem of applied problems. Network designers use MSTs to lay fibre-optic cables at minimum cost; bioinformaticians build phylogenetic trees by treating genetic distance as an edge weight; machine-learning engineers initialise clustering hierarchies from MST structure. Each domain reuses the same theorem in a new disguise.

Choose the application that speaks most directly to your own field and follow it one level deeper: the reward is discovering that an abstract graph-theoretic proof, once understood, purchases insight across disciplines you may never have expected to be connected.
