Polynomial Time

Definition. An algorithm runs in polynomial time if there exists a polynomial $p$ such that, for every input of size $n$, the algorithm terminates in at most $p(n)$ elementary operations. Formally, we write the worst-case time complexity as $T(n) = O(n^k)$ for some fixed constant $k \geq 0$. The class of all decision problems solvable by a deterministic algorithm in polynomial time is denoted $\mathbf{P}$.

The choice of $n$ as the input size is deliberate: for a graph with $V$ vertices and $E$ edges, $n = |V| + |E|$; for an integer $m$, $n = \lfloor \log_2 m \rfloor + 1$, the number of bits required to encode $m$. This encoding convention ensures that input size reflects the actual information content of the data, not an incidental numeric magnitude.

Worked Example. Consider sorting an array of $n$ integers with Merge Sort. At each recursive level the algorithm performs $O(n)$ comparisons, and the recursion depth is $\lceil \log_2 n \rceil$, giving $T(n) = O(n \log n)$. Since $\log n \leq n$ for all $n \geq 1$, we have $T(n) = O(n^2)$, confirming that Merge Sort lies in $\mathbf{P}$ with $k = 2$. By contrast, naive enumeration of all subsets of an $n$-element set requires $2^n$ steps — exponential growth that no polynomial dominates for large $n$.

Key Theorem (Cobham–Edmonds Thesis). The class $\mathbf{P}$ is robust: it is invariant under changes of reasonable computational model (Turing machines, RAM machines, circuit families of polynomial size) and under polynomial changes of encoding. Consequently, membership in $\mathbf{P}$ is a meaningful, model-independent certificate of tractability.

This robustness justifies treating $\mathbf{P}$ as the formal boundary between feasible and infeasible computation, underpinning the celebrated open question of whether $\mathbf{P} = \mathbf{NP}$.

Lab Cell.

from sympy import symbols, O, log

n = symbols('n', positive=True)

merge_sort  = n * log(n)   # Merge Sort work
exponential = 2**n         # brute-force enumeration

print(O(merge_sort, n))           # O(n*log(n))
print(merge_sort.subs(n, 1000))   # ≈ 9965
print(exponential.subs(n, 100))   # > 10^30

Running this cell makes the gulf between polynomial and exponential growth concrete: at $n = 100$, Merge Sort performs roughly $10^4$ operations while brute-force enumeration demands more than $10^{30}$ — computationally unreachable on any foreseeable hardware.
