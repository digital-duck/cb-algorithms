Concept Book: Memoization

Algorithms Ch07 · Generated by SPL

Payoff

Memoization is the disciplined refusal to recompute what has already been computed. More precisely, given a pure function $f : X \to Y$, memoization augments $f$ with a cache $M : X \rightharpoonup Y$ (a partial map) so that the first call $f(x)$ writes $M[x] \leftarrow f(x)$, and every subsequent call with the same argument returns $M[x]$ directly, in $O(1)$ time. The correctness guarantee rests on referential transparency: because $f$ is pure, the cached value is forever identical to what recomputation would produce. The efficiency guarantee is that the total number of distinct subproblem evaluations is bounded by $|X|$, the size of the input domain, regardless of how many times those subproblems are requested.

Why is memoization the natural endpoint of this arc? Every concept developed in the preceding chapters—recursion, call graphs, topological order, and asymptotic complexity—converges here. A recursive algorithm induces a directed acyclic graph (DAG) of subproblem dependencies; topological order reveals that each node need be evaluated exactly once if results flow from leaves to root; memoization is the mechanism that enforces this discipline automatically, without requiring the programmer to manage an explicit evaluation schedule.

Connection to longest path in a DAG. Let $G = (V, E, w)$ be a weighted DAG with edge weights $w : E \to \mathbb{R}$. Define $L(v)$ as the length of a longest path ending at vertex $v$. The recurrence is

$$L(v) = \max\!\Bigl(\{0\} \cup \bigl\{L(u) + w(u,v) : (u,v)\in E\bigr\}\Bigr).$$

A naïve recursive evaluation of $L(v)$ re-explores shared ancestors exponentially. With memoization, each $L(v)$ is computed once and stored; the total work is $O(|V| + |E|)$—linear in the graph's size. The cache implicitly performs the topological sweep: a vertex's value is cached before any descendant requests it, because recursion unwinds in reverse topological order.

Worked example. Consider the DAG with vertices $\{s, a, b, t\}$ and edges $s\!\to\!a\ (3),\ s\!\to\!b\ (1),\ a\!\to\!t\ (4),\ b\!\to\!t\ (7)$. Evaluating $L(t)$ recursively calls $L(a)$ and $L(b)$; each calls $L(s)=0$. Without memoization, $L(s)$ is evaluated twice. With memoization, $M[s]=0$ is stored on the first call; the second call returns immediately. The final answer is $L(t)=\max(L(a)+4,\, L(b)+7)=\max(7,8)=8$.

import sympy as sp
from functools import lru_cache

edges = {('s','a'):3, ('s','b'):1, ('a','t'):4, ('b','t'):7}
predecessors = {'s':[], 'a':['s'], 'b':['s'], 't':['a','b']}

@lru_cache(maxsize=None)
def L(v):
    preds = predecessors[v]
    if not preds:
        return 0
    return max(L(u) + edges[(u, v)] for u in preds)

print({v: L(v) for v in predecessors})   # {'s':0,'a':3,'b':1,'t':8}

The journey from the definition of memoization to a linear-time longest-path algorithm is short precisely because the concept was designed with this application in mind. To see how the same principle extends to weighted scheduling, sequence alignment, and resource-constrained planning, proceed to the chapter on Longest Path in a DAG, where the recurrence above becomes the skeleton of a full dynamic programming analysis.
