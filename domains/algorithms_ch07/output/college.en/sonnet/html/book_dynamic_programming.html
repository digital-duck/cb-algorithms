Payoff

Dynamic programming is not merely a technique for speeding up recursive computations — it is a disciplined way of thinking about optimal substructure. When a problem can be decomposed so that the solution to each sub-instance depends only on the solutions to strictly smaller sub-instances, dynamic programming converts an exponential search into a polynomial one by ensuring each sub-instance is solved exactly once. The resulting algorithm fills a table of sub-problem answers in a carefully chosen order and reads the global optimum from a single table cell. This shift — from recomputation to systematic memoization — is the intellectual payoff of every concept developed in the preceding sections of this text.

Definition. A problem exhibits optimal substructure if an optimal solution to the whole necessarily contains optimal solutions to its parts. Formally, let $\mathcal{P}$ be a problem on input of size $n$, and let $\text{OPT}(k)$ denote the optimal value for input of size $k \le n$. Dynamic programming applies whenever $\text{OPT}(n)$ can be expressed as a function of $\{\text{OPT}(k) : k < n\}$ that is computable in polynomial time given those values.

Worked example. Consider the classic 0–1 knapsack: $n$ items with weights $w_1,\dots,w_n$ and values $v_1,\dots,v_n$, and a capacity $W$. Define $\text{OPT}(i, c)$ as the maximum value achievable using the first $i$ items with capacity $c$. The recurrence

$$\text{OPT}(i,c) = \max\!\bigl(\text{OPT}(i-1,c),\; v_i + \text{OPT}(i-1, c - w_i)\bigr)$$

fills an $n \times W$ table in $O(nW)$ time, yielding the global optimum at $\text{OPT}(n,W)$.

Key theorem (Principle of Optimality, Bellman 1957). If a policy $\pi^$ is globally optimal for a sequential decision problem, then for every intermediate state $s$ reached by $\pi^$, the sub-policy of $\pi^*$ from $s$ onward is optimal for the sub-problem starting at $s$.

# Lab cell — verify the knapsack DP with SymPy/Python
from sympy import symbols, Max

weights = [2, 3, 4, 5]
values  = [3, 4, 5, 6]
W       = 5
n       = len(weights)

OPT = [[0] * (W + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    for c in range(W + 1):
        take = values[i-1] + OPT[i-1][c - weights[i-1]] if c >= weights[i-1] else 0
        OPT[i][c] = max(OPT[i-1][c], take)

print("Maximum value:", OPT[n][W])   # Expected: 7

The natural endpoint. Every concept in this book — graph reachability, topological order, acyclic structure — converges here. Dynamic programming is the algorithm that needs a DAG: subproblem dependencies must be acyclic for the table-filling order to exist. The relationship is not coincidental; it is structural. This is precisely why the longest-path problem in a directed acyclic graph is the canonical first application: it strips away all distractions and shows the recurrence, the topological evaluation order, and the traceback in their purest form.
