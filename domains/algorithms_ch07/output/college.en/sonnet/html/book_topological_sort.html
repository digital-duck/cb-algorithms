Concept Book: Topological Sort

Algorithms Ch07 · Generated by SPL

Payoff

A directed acyclic graph (DAG) encodes dependency: an edge $u \to v$ declares that $u$ must precede $v$. Topological sorting linearizes this partial order into a total order $\sigma$ such that for every edge $u \to v$ in $G$, the position of $u$ in $\sigma$ is strictly less than the position of $v$. Formally, given a DAG $G = (V, E)$, a topological sort is a bijection $\sigma: V \to \{1, 2, \ldots, |V|\}$ satisfying

$$ (u, v) \in E \implies \sigma(u) < \sigma(v). $$

Such an ordering exists if and only if $G$ is acyclic—a fact whose proof follows directly from the observation that a cycle would force $\sigma(u) < \sigma(u)$, a contradiction. Kahn's algorithm computes $\sigma$ in $O(|V| + |E|)$ by repeatedly extracting vertices of in-degree zero, while the DFS-based variant records finish times and reverses them. Both procedures are efficient, exact, and serve as the canonical endpoint of a journey through graph structure: once you can order vertices consistently with their dependencies, an enormous class of computational problems becomes tractable.

Worked example. Consider the DAG with vertices $\{A, B, C, D\}$ and edges $A \to C$, $B \to C$, $C \to D$. Running Kahn's algorithm: sources at round 1 are $\{A, B\}$; removing them exposes $C$; removing $C$ exposes $D$. One valid topological sort is $A, B, C, D$—and this ordering is precisely what a build system uses to compile $A$ and $B$ before their shared dependency $C$, and $C$ before $D$.

Key theorem (optimal substructure via topological order). The connection to dynamic programming is not incidental. For any DAG whose vertices represent subproblems and whose edges represent dependencies, processing vertices in topological order guarantees that every subproblem is solved before it is needed. Concretely, the recurrence for the longest path in a DAG,

$$ d[v] = \max_{(u,v)\in E}\bigl(d[u] + w(u,v)\bigr), $$

is well-defined and computable in $O(|V|+|E|)$ time if and only if $v$ is visited after all its predecessors—exactly the guarantee topological sort provides. Without this ordering, the recurrence is circular; with it, each value is computed exactly once.

# Lab cell — topological sort and longest path in SymPy / pure Python
import sympy as sp
from collections import deque

edges = [('A','C'), ('B','C'), ('C','D')]
vertices = ['A','B','C','D']
weights = {e: 1 for e in edges}

in_deg = {v: 0 for v in vertices}
adj = {v: [] for v in vertices}
for u, v in edges:
    adj[u].append(v); in_deg[v] += 1

queue = deque(v for v in vertices if in_deg[v] == 0)
topo, dist = [], {v: 0 for v in vertices}
while queue:
    u = queue.popleft(); topo.append(u)
    for v in adj[u]:
        dist[v] = max(dist[v], dist[u] + weights[(u,v)])
        in_deg[v] -= 1
        if in_deg[v] == 0: queue.append(v)

print("Order:", topo)
print("Longest distances:", dist)

Topological sort is the natural endpoint of this text because it is the structural prerequisite for the most powerful algorithmic paradigm in discrete mathematics. Every chapter—from graph traversal to cycle detection—has been building the vocabulary needed to state and prove that a DAG's vertices can always be processed in dependency order. The reward is immediate: dynamic programming on DAGs, which subsumes shortest-path problems, sequence alignment, optimal scheduling, and compiler register allocation under a single framework. If you wish to see this power in full, turn to the chapter on dynamic programming, where the longest-path recurrence above is generalized to solve the classic 0/1 knapsack, edit distance, and weighted interval scheduling problems—each one a DAG in disguise.
